Bir Soz API contract — current extension (legacy 0.1.1 is different)

Destination: https://api.lukivan8.com. Three fixed paths below; no arbitrary-URL
transport and no network sender in the content script. credentials:'omit' on
all three requests. Timeout:15 seconds. No cookies/account/authentication token.
Full field types, enums, required properties and error schemas: api-schemas.json.

GET /api/v1/vocabularies
Purpose: download complete catalog/words as JSON data. Analytics consent is NOT
required. No request body or installation ID. Optional X-Bir-Organization-Code
header from explicit organization connection; optional If-None-Match from cache.
200: RemoteVocabularyCatalog; ETag retained. 304: retain cache (must exist).
Catalog fields: protocolVersion, version, vocabularies. Each vocabulary contains
id/name/optional description/level/version/requiresOrganization/updatedAt/words;
word fields id/kk/ru/level. level remains a compatibility field; tasks are direct
translation. All responses validated before complete atomic local merge.
Triggers: installation/update, worker startup, 15-minute alarm, explicit retry,
and successful connect. Failures keep last valid cache. No bundled fallback on
a fresh offline install. Simultaneous sync coalesced; changed code context retried.

POST /api/v1/organization/connect
Purpose: explicit optional code connection, independent of learning consent.
Body ConnectRequest: installationId (random persistent UUID), code (trimmed text).
Response ConnectResponse: organization {id,name,code}, extraVocabularyEnabled.
Same-code retry is idempotent. No automatic arbitrary switching/disconnection UI.
Errors validated as ProtocolError: CODE_NOT_FOUND and CODE_DISABLED explained in
Russian; other errors get generic UI text. Network failure: user retries.
Connection and subsequent catalog use persist across restarts. Organization
archival removes gated cache availability on next successful catalog update,
while SRS/history and the existing connection remain locally preserved.
Server stores connection date. The authenticated team dashboard displays an
organization-scoped pseudonym and connection date, even with learning consent off.

POST /api/v1/analytics/events/batch
Purpose: optional learning analytics; disabled by default, controlled in settings.
Body AnalyticsBatchRequest: {events: AnalyticsEventV2[]}.
Current client sends at most50 events per batch (server schema accepts up to500).
Required common fields: id, installationId, type, occurredAt (epoch milliseconds).
Optional organizationId is included when connected; never the organization code.
Events emitted by the client:
- onboarding_started/completed: common fields
- onboarding_step_completed: onboardingStep (skipped step uses ':skipped' suffix)
- organization_connected: organizationId
- dictionary_activated: vocabularyId
- study_session_started/completed: sessionId,vocabularyId; no duration
- study_card_rated: sessionId,vocabularyId,wordId,confidence(-2..2),durationMs
- challenge_completed: vocabularyId,wordId,correct,durationMs
- challenge_skipped: vocabularyId,wordId; no duration
Only server dictionary/word IDs are eligible. Custom texts/IDs/progress are not
uploaded. Sessions containing custom cards emit only server-card events.
Raw duration is sent unchanged. Server alone counts answer<=120s plus10s;
longer responses count10s, skips/sessions add0 (no double counting).

Response AnalyticsBatchResponse: accepted,duplicates,rejected[{id,code}].
Validate schema and batch counts/rejected IDs before deleting acknowledged items.
Stable event IDs permit server deduplication on retry. Permanent per-event
rejections are removed; HTTP/network/schema errors retain the batch. One-minute
alarm retries, draining in batches; concurrent flushes serialize via Web Locks.
Consent is checked under the storage lock before dispatch. Opt-out clears the
current v2 queue and aborts active fetch; already received requests cannot be
retracted. No new learning events while off. Local progress still works.
Legacy queues may remain locally from0.1.1; this version does NOT transmit them
or create duplicate v2 copies. No daily snapshots or legacy endpoint requests.
Public organization analytics exposes total metrics and last completed challenge
time next to the member pseudonym; no raw installation UUID or event-by-event log.

Excluded from every learning payload: visited URL/title/content, form values,
passwords,cookies,history,clicked links,selectors,screenshots,custom vocabulary
text/names/IDs, email/account/hardware/advertising IDs, organization code.
API/infrastructure necessarily processes network metadata such as IP in transit;
the application request logger emits only method/route-template/status/duration.
See public policy for retention, infrastructure processors and restricted team access.


Version 0.2.2: renewed analytics consent

Analytics now requires a decision for the current data-practice version, not
just the legacy analyticsEnabled setting. On upgrade, old permission is paused
and pending v2 and legacy analytics queues are discarded. No new learning
events are created until explicit consent. A one-time update tab explains the
choice; an unanswered choice stays visible in the extension without blocking
learning. Refusal and acceptance persist across ordinary subsequent updates.
Changing the decision is available in Settings. Local progress, vocabulary,
organization connection and installation identity are retained. Already received
server records are not deleted. Catalog downloads and optional organization
connection remain independent of learning-analytics consent.
