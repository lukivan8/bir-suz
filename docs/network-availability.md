# Недоступность каталога в корпоративных сетях

**Решение (8 октября 2026):** `https://www.birsoz.kz/api/v1/vocabularies` проксирует
API через Vercel и подтверждённо открывается из затронутых корпоративных сетей.
С версии 0.2.4 расширение использует `https://www.birsoz.kz` по умолчанию; старый
`https://api.lukivan8.com` остаётся для установленных 0.2.3 и ниже. Ниже — история
диагностики.

Проверка 21 сентября 2026 года из доступной разработчику сети:

- GET `https://api.lukivan8.com/api/v1/vocabularies` возвращает 200 и валидный JSON каталога. Ответ проходит через Cloudflare.
- `https://birsoz.kz/api/v1/vocabularies` перенаправляет на www и возвращает 404. Сайт обслуживается Vercel. Это пока не альтернативный API.
- Причина недоступности из сети пользователя не установлена. Доступность сайта не исключает фильтрацию имени API, DNS, IP/маршрута или проблему TLS.
- STS описывает web- и DNS-фильтрацию ЕШДИ: https://sts.kz/ru/eshdi. Для обращения указан https://support.sts.kz.

## Следующий шаг диагностики

Открыть точный URL каталога из затронутой сети и записать код ошибки браузера либо текст страницы блокировки, время и организацию/провайдера. Сравнить с мобильной сетью на том же устройстве. Через администратора сети проверить DNS и причину отказа в журнале шлюза; при фильтрации подать заявку на проверку категории/разрешение доступа в STS. Не отправлять коды организаций или локальный storage в диагностику.

Если переносить API под домен продукта, сначала развернуть и проверить маршрут (например, `/api/v1/` на домене сайта), включая каталог, ETag, подключение организации и аналитику; лишь затем менять API_ORIGIN и host_permissions расширения. Новый адрес обязательно проверить из затронутой сети: новое имя само по себе не гарантирует доступность. Старый endpoint нужен на период обновления установленных расширений.

## Исправление интерфейса

При `catalogVersion === null` предупреждение видно над основным интерфейсом popup и dashboard, а также в модальном окне изучения слов. Оно объясняет отсутствие заданий, предлагает повторную загрузку и WhatsApp. Повторная загрузка блокирует повторные клики, показывает занятость, обрабатывает `{ok:false}` и отклонение сообщения. Ссылка поддержки также постоянно доступна в popup/dashboard и при ошибке учебной карточки. До загрузки каталога кнопка примера задания выключена.

Номер меняется в `src/components/SupportLink.tsx`. Переход открывает WhatsApp, сообщение автоматически не отправляется.
